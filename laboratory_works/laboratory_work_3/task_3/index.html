    Подзадача 3. Вызов парсера из FastAPI через очередь Celery + Redis

    Постановка задачи

    В третьей подзадаче требовалось реализовать асинхронный вызов парсера через очередь задач.
    Смысл этой части работы в том, чтобы не выполнять долгую операцию парсинга прямо внутри HTTP-запроса, а передать её в фон.

    Что реализовано

    В проект были добавлены:

    • redis — брокер сообщений;
    • worker — Celery worker;
    • beat — Celery Beat;
    • parser/celery_app.py — конфигурация Celery;
    • parser/tasks.py — задачи Celery;
    • маршруты FastAPI для постановки задачи и проверки статуса.

    Маршруты API

    В app/main.py реализованы:

    • POST /parse-async — ставит задачу в очередь;
    • GET /tasks/{task_id} — возвращает статус задачи и результат.

    Как работает асинхронный сценарий

    Шаг 1. Клиент вызывает /parse-async

    FastAPI получает URL и создаёт Celery-задачу:

    • tasks.parse_url_task

    В ответ API сразу возвращает:

    • task_id
    • статус queued

    Шаг 2. Redis хранит задачу

    Redis выступает брокером и передаёт задачу worker-процессу.

    Шаг 3. Worker выполняет задачу

    В parser/tasks.py задача parse_url_task вызывает:

    • fetch_and_parse(url)
    • save_book(...)

    То есть фоновая задача использует ту же основную логику парсинга, что и HTTP-вызов.

    Шаг 4. Клиент проверяет статус

    По task_id клиент может обратиться к маршруту /tasks/{task_id} и узнать:

    • PENDING
    • STARTED
    • SUCCESS
    • FAILURE

    Повторные попытки

    Для parse_url_task настроены:

    • max_retries=2
    • default_retry_delay=10

    Это значит, что при ошибке Celery может повторить задачу.

    Периодические задачи

    В parser/celery_app.py настроен beat_schedule.

    По расписанию запускается задача:

    • tasks.cleanup_parser_books_task

    Она вызывает очистку импортированных книг парсера.

    Что можно показать на защите

    1. Открыть http://localhost:8000/docs
    2. Вызвать POST /parse-async
    3. Получить task_id
    4. Вызвать GET /tasks/{task_id}
    5. Показать статус и результат
    6. Показать логи worker и beat

    Вывод

    В третьей подзадаче реализована фоновая обработка парсинга через Celery и Redis.
    FastAPI ставит задачу в очередь, worker выполняет её в фоне, а результат можно получить по task_id.
    Дополнительно настроена периодическая задача очистки через Celery Beat.
