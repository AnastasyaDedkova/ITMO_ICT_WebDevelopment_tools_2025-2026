# Подзадача 2. Вызов парсера из FastAPI по HTTP

## Постановка задачи

Во второй подзадаче требовалось реализовать вызов парсера из FastAPI через HTTP.  
Пользователь должен иметь возможность отправить URL в API и получить результат парсинга.

## Что реализовано

В `app/main.py` реализован маршрут:

- `POST /parse`

Он принимает JSON с URL, затем отправляет запрос в отдельный parser-сервис и возвращает ответ клиенту.

## Как это работает

### Шаг 1. Клиент отправляет запрос в API

Пользователь обращается к FastAPI по маршруту `/parse` и передаёт URL книги.

### Шаг 2. API обращается к parser-сервису

FastAPI использует `httpx.AsyncClient` и отправляет POST-запрос во внутренний сервис parser по маршруту `/parse`.

### Шаг 3. Parser загружает страницу и извлекает данные

В `parser/main.py` входной URL передаётся в функции:

- `fetch_and_parse(...)`
- `save_book(...)`

Логика парсинга вынесена в `parser/parser_core.py`.

## Что делает parser

В `parser/parser_core.py` реализованы:

- проверка допустимости URL;
- загрузка HTML страницы;
- извлечение названия книги;
- извлечение автора;
- извлечение описания;
- извлечение года публикации;
- сохранение книги в PostgreSQL.

## Защита от дублей

Перед сохранением выполняется проверка, есть ли уже такая книга в базе.  
Если запись уже существует, новая запись не создаётся повторно.

## Модели базы данных

Для сохранения используются модели:

- `User`
- `Book`
- `Genre`
- `BookGenreLink`

Они описаны в `parser/models.py`.

## Что можно показать на защите

Через Swagger API:

- открыть `http://localhost:8000/docs`
- выбрать маршрут `POST /parse`
- отправить URL книги Project Gutenberg
- получить результат парсинга

После этого можно показать, что книга записалась в PostgreSQL.

## Вывод

Во второй подзадаче реализован вызов парсера из FastAPI через HTTP.  
FastAPI выступает как внешняя точка входа, а parser работает как отдельный внутренний сервис, который выполняет парсинг и сохраняет данные в базу.
