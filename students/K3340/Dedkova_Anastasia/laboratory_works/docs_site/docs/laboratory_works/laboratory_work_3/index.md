# Лабораторная работа 3

## Тема
Упаковка FastAPI-приложения в Docker, работа с источниками данных и очереди.

## Цель работы
Научиться упаковывать FastAPI-приложение, базу данных и парсер в Docker, вызывать парсер через HTTP и через очередь задач Celery + Redis.

## Общая структура проекта

В проекте выделены следующие основные части:

- `app/` — FastAPI API, через которое пользователь взаимодействует с системой;
- `parser/` — отдельный сервис парсера, который загружает страницу, извлекает данные и сохраняет их в базу данных;
- `tests/` — тесты API;
- `docker-compose.yml` — orchestration-файл для запуска всех сервисов.

## Основные сервисы системы

Через Docker Compose поднимаются следующие сервисы:

- `api` — FastAPI-приложение;
- `parser` — сервис парсера;
- `db` — PostgreSQL;
- `redis` — брокер сообщений;
- `worker` — Celery worker;
- `beat` — Celery Beat для периодических задач.

## Что реализовано в лабораторной

Лабораторная работа состоит из трёх подзадач:

1. Упаковка FastAPI, базы данных и парсера в Docker.
2. Вызов парсера из FastAPI по HTTP.
3. Вызов парсера из FastAPI через очередь Celery + Redis.

## Как запустить проект

### Первый запуск
```bash
docker compose up --build
````

### Повторный запуск без пересборки

```bash
docker compose up
```

или

```bash
docker compose start
```

### Остановка

```bash
docker compose stop
```

## Swagger

После запуска доступны:

* API: `http://localhost:8000/docs`
* Parser: `http://localhost:8001/docs`

## База данных

PostgreSQL доступен по параметрам:

* host: `localhost`
* port: `5433`
* database: `bookcrossing`
* user: `postgres`
* password: `postgres`

## Итог

В лабораторной реализована контейнеризированная система, в которой FastAPI может:

* вызывать парсер напрямую по HTTP;
* ставить задачу на парсинг в очередь;
* получать статус фоновой задачи;
* работать с PostgreSQL как с общей базой данных.
